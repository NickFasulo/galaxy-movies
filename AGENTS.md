# Galaxy Movies

Next.js 15 Pages Router app (React 19, Chakra UI, @tanstack/react-query v5). All application code is strict TypeScript under `src/` — `allowJs` is off, so new source files must be `.ts`/`.tsx`.

## Commands

- `npm run typecheck` — `tsc --noEmit`
- `npm test` — Vitest unit tests, colocated as `src/**/*.test.ts`
- `npm run lint` — ESLint flat config (`eslint.config.mjs`, `next/core-web-vitals` + `next/typescript`)
- `npm run check` — typecheck + production build
- `npm run dev` — dev server on :3000

## Deploys

Vercel auto-deploys **previews only** — `vercel.json` sets `git.deploymentEnabled.main: false`, so merging to `main` never ships to production on its own. To release, open the PR's preview deployment in the Vercel dashboard and click **Promote to production** (or `vercel promote <preview-url>`). Crons keep running on the current production deployment. Commits that only touch docs/CI config skip preview builds via `ignoreCommand` in vercel.json. Branch protection on `main` requires a PR with a green `check` job (`ci.yml`: typecheck, lint, test, build).
- `npm run lhci` — build + Lighthouse CI (`lighthouserc.cjs`)

## Conventions

- Shared TMDB/API types live in `src/types/tmdb.ts`; env var declarations in `src/types/env.d.ts`.
- Design tokens live in `src/theme.ts` (Chakra `createSystem`): `surface.*` colors, `brand.*` accents, `border.subtle`, and the `fonts.display` brand face — use them instead of hardcoding the dark grays. Body font is self-hosted Inter (`public/fonts/inter-var-latin.woff2`, `@font-face` in globals.css); `next/font` can't be used in `_document` on the Pages Router, so fonts are always self-hosted there. The `Inter-*.ttf` files are for `next/og` only.
- Detail pages with server-side error props split the error view into a separate component so hooks never run conditionally (see `CompanyContent`/`CompanyErrorView` pattern).
- `src/pages/api/og.tsx` renders `next/og` markup — raw `<img>` is required there and ESLint rules are disabled for that file only.
- All backdrop imagery renders through `src/components/Backdrop.tsx` (`BACKDROP_OVERLAYS` gradient presets, `BACKDROP_FALLBACKS` local art). Local art is generated by `node scripts/generate-backdrop-fallback.js` (seeded, deterministic). The card-hover backdrop swap is homepage-only: `useHoverBackground` + `<HoverBackground>` in `src/components/HoverBackground.tsx`, wired in `src/pages/index.tsx`. It must render inside the page's `zIndex={1}` content box — mounted in `_app`, the root Flex's opaque `bg` paints over it.
- `scripts/` is plain JS build tooling, excluded from tsconfig and ESLint.
- Upstash free tier bills every command — including each member of a pipeline — so per-request paths must minimize Redis ops: prefer `HGETALL`/`MGET`/hash storage over per-key fan-out, batch counter updates in memory before flushing, and don't add Redis reads to SSR hot paths without counting the quota cost.

## Watchlist alerts

Alerts give a confirmed waitlist subscriber (`gm:waitlist:confirmed`, email → unsub token) a separate, independently-rotatable credential — `gm:alerts:synckey` (email → UUID) — minted on first confirm and handed out via URL fragment (`/email-status#email=&key=`) so it never hits server access logs. The client stores it (`gm.alerts.v1` in localStorage) and posts debounced watchlist/service snapshots to `POST /api/alerts-prefs`, stored in `gm:alerts:prefs` (email → `{watchlist, services, region, updatedAt}`). `GET /api/alerts-link?email&key` re-issues the fragment for linking additional devices; `waitlist.ts` emails that link automatically when an already-confirmed address re-submits the form. The daily `/api/cron/watchlist-alerts` cron (runs after `streaming-changes`) reads `streaming-changes`'s cached diffs, matches each subscriber's watchlist against their chosen providers' `added`/`coming` titles, dedupes against `gm:alerts:notified`, and sends one Resend email per subscriber with matches. Unsubscribing (`waitlist-remove.ts`) clears all three `gm:alerts:*` hash entries for that email.

## Environment

Copy `.env.example` (if present) or set: `TMDB_API_KEY`, `NEXT_PUBLIC_SITE_URL`, `UPSTASH_REDIS_KV_REST_API_URL`, `UPSTASH_REDIS_KV_REST_API_TOKEN`, `OPENAI_API_KEY`, `WATCHMODE_API_KEY`, `RESEND_API_KEY`, `CRON_SECRET`, `TAKEADS_PUBLIC_KEY`. Without `TAKEADS_PUBLIC_KEY`, watch-provider links fall back to plain provider homepages instead of affiliate tracking links. Optional: `WATCHMODE_DAILY_LOOKUP_BUDGET` (default 300), `RESEND_FROM`, `NEXT_PUBLIC_UMAMI_WEBSITE_ID` (Umami analytics; has a committed fallback ID so it works with no env). The tracker script and its `/api/send` beacon are proxied first-party via `rewrites()` in `next.config.ts` (`/assets/starfield.js`, `/starfield/api/send`) because the umami.is origins are ad-blocked; `NEXT_PUBLIC_UMAMI_SRC` overrides the script URL — an external/self-hosted origin also needs CSP entries there. Never commit `.env.local`.

For OpenAI spend/usage reporting, run `OPENAI_ADMIN_KEY=... node scripts/openai-usage.js [days]` — requires an org admin key, not the runtime `OPENAI_API_KEY`. Optional: `OPENAI_MODEL` overrides the shared model in `src/utils/openai.ts` (default `gpt-6-luna`, `reasoning_effort: none`); bump the `*_CACHE_VERSION` constants when switching models so cached generations don't mix.
