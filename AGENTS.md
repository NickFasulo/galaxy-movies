# Galaxy Movies

Next.js 15 Pages Router app (React 19, Chakra UI, @tanstack/react-query v5). All application code is strict TypeScript under `src/` — `allowJs` is off, so new source files must be `.ts`/`.tsx`.

## Commands

- `npm run typecheck` — `tsc --noEmit`
- `npm test` — Vitest unit tests, colocated as `src/**/*.test.ts`
- `npm run lint` — ESLint flat config (`eslint.config.mjs`, `next/core-web-vitals` + `next/typescript`)
- `npm run check` — typecheck + production build
- `npm run dev` — dev server on :3000 (webpack). `npm run dev:turbo` runs Turbopack, but Next 16.4.0 has a Pages Router Turbopack dev bug (vercel/next.js#99789) that hydration-crashes pages with "module factory is not available" — keep `dev` on webpack until the backported fix ships, then swap the flags back.

## Deploys

**Production = Cloudflare Workers.** `galaxymovies.app` DNS is on Cloudflare; `npm run cf:deploy` builds + deploys the Worker to the custom domain. `main` is unprotected — **commit and push directly to `main` by default**; only use a branch for large implementations that warrant a plan/review. `ci.yml` still runs `check` (typecheck, lint, test, build) on pushes and PRs. Merged PR branches auto-delete.

Vercel is **cold standby only** — no domain points at it, its crons are disabled (dashboard → Settings → Cron Jobs), and `git.deploymentEnabled.main: false` keeps `main` pushes from auto-deploying. Rollback = re-add `A galaxymovies.app → 216.198.79.1` + `CNAME www → 2144276a1a31ddeb.vercel-dns-017.com` in Cloudflare DNS (traffic flips back instantly — Worker custom domains only take precedence while they're the only records), re-enable Vercel crons. Vercel teardown checklist once fully decommissioned: remove the domain from the project, delete crons, downgrade team to Hobby/cancel Pro. Previews still work via `vercel deploy --scope nickfasulos-projects`. Commits that only touch docs/CI config skip preview builds via `ignoreCommand` in vercel.json.
- `npm run lhci` — build + Lighthouse CI (`lighthouserc.cjs`)

## Cloudflare Workers deploy

The app runs on Cloudflare Workers via `@opennextjs/cloudflare` (deployed to `galaxymovies.app` + `www` custom domains; `galaxy-movies.winter-rice-c91a.workers.dev` also stays live). `npm run cf:build` runs the adapter build plus `scripts/opennext-postbuild.js`, which (a) drops stub modules for dev-only `require()`s the adapter marks external (see `patches/@opennextjs+cloudflare+*.patch`, applied by `postinstall` — re-run `npx patch-package @opennextjs/cloudflare` if edits drift), (b) copies `public/fonts` + `backdrop_fallback.jpg` to `.open-next/public/` because workerd's `fs` cwd is `/bundle`, and (c) writes `.open-next/entry.js` — the worker entry that wraps the generated `worker.js` with a `scheduled()` handler reproducing the `vercel.json` crons via the `WORKER_SELF_REFERENCE` service binding (same `Bearer CRON_SECRET` auth). `wrangler.jsonc` sets `main` to that entry, `triggers.crons`, the `NEXT_INC_CACHE_R2_BUCKET` R2 binding (ISR cache — create the bucket once: `wrangler r2 bucket create galaxy-movies-inc-cache`), and `find_additional_modules` + `rules` so the og fonts ship in the vfs. `npm run cf:preview` builds + `wrangler dev` (add `--test-scheduled` to fire crons at `/__scheduled?cron=<expr>`); `npm run cf:secrets` pushes `.env.local` values as worker secrets; `npm run cf:deploy` builds + deploys to `galaxy-movies.<account>.workers.dev`. `/api/og` imports `@vercel/og`'s edge entry on workerd (detected via `navigator.userAgent === 'Cloudflare-Workers'`) because the node entry uses `readFileSync` + runtime `WebAssembly.instantiate`, both disallowed; `useWorkerdCondition` externals force-copy emotion/uncrypto packages whose ESM builds sit behind `workerd` export conditions. Node APIs are fetch-only (Upstash REST, OpenAI, Resend) — no TCP clients, so nothing else needs polyfills.

## Conventions

- Shared TMDB/API types live in `src/types/tmdb.ts`; env var declarations in `src/types/env.d.ts`.
- Design tokens live in `src/theme.ts` (Chakra `createSystem`): `surface.*` colors, `brand.*` accents, `border.subtle`, and the `fonts.display` brand face — use them instead of hardcoding the dark grays. Body font is self-hosted Inter (`public/fonts/inter-var-latin.woff2`, `@font-face` in globals.css); `next/font` can't be used in `_document` on the Pages Router, so fonts are always self-hosted there. The `Inter-*.ttf` files are for `next/og` only.
- Detail pages with server-side error props split the error view into a separate component so hooks never run conditionally (see `CompanyContent`/`CompanyErrorView` pattern).
- `src/pages/api/og.tsx` renders `next/og` markup — raw `<img>` is required there and ESLint rules are disabled for that file only.
- `src/utils/imageLoader.ts` is the global `next/image` loader — referenced by `next.config.ts` `images.loaderFile` as a string path, so import-graph/dead-code scans can't see it. Do not delete it.
- All backdrop imagery renders through `src/components/Backdrop.tsx` (`BACKDROP_OVERLAYS` gradient presets, `BACKDROP_FALLBACKS` local art). Local art is generated by `node scripts/generate-backdrop-fallback.js` (seeded, deterministic); the /plus page's spiral-galaxy variant is `node scripts/generate-plus-backdrop.js` (`BACKDROP_FALLBACKS.plus`), and the PWA/touch icons in `public/icons/` are `node scripts/generate-icons.js` (centered spiral; maskable variants shrink the galaxy into the 80% safe zone). `public/sw.js` is a push-only service worker (no fetch handler — it never touches page loads). The card-hover backdrop swap is homepage-only: `useHoverBackground` + `<HoverBackground>` in `src/components/HoverBackground.tsx`, wired in `src/pages/index.tsx`. It must render inside the page's `zIndex={1}` content box — mounted in `_app`, the root Flex's opaque `bg` paints over it.
- `scripts/` is plain JS build tooling, excluded from tsconfig and ESLint.
- Upstash free tier bills every command — including each member of a pipeline — so per-request paths must minimize Redis ops: prefer `HGETALL`/`MGET`/hash storage over per-key fan-out, batch counter updates in memory before flushing, and don't add Redis reads to SSR hot paths without counting the quota cost.

## Watchlist alerts

Alerts give a confirmed waitlist subscriber (`gm:waitlist:confirmed`, email → unsub token) a separate, independently-rotatable credential — `gm:alerts:synckey` (email → UUID) — minted on first confirm and handed out via URL fragment (`/email-status#email=&key=`) so it never hits server access logs. The client stores it (`gm.alerts.v1` in localStorage) and posts debounced watchlist/ratings/service snapshots to `POST /api/alerts-prefs`, stored in `gm:alerts:prefs` (email → `{watchlist, services, region, ratings, updatedAt}`). `GET /api/alerts-prefs?email&key` returns the snapshot; on confirm, `email-status.tsx` merges it into local storage (`mergeSyncedPrefs`, local wins conflicts) so new devices inherit the profile instead of overwriting it. `GET /api/alerts-link?email&key` re-issues the fragment for linking additional devices; `waitlist.ts` emails that link automatically when an already-confirmed address re-submits the form. The daily `/api/cron/watchlist-alerts` cron (runs after `streaming-changes`) reads `streaming-changes`'s cached diffs, matches each subscriber's watchlist against their chosen providers' `added`/`coming` titles (plus `leaving`/`taste` for Plus subscribers), dedupes against `gm:alerts:notified`, and sends one Resend email per subscriber with matches. Free subscribers match only the base six providers; Plus subscribers match every source in `PROVIDER_NAME_MATCH` — peacock/paramount+ diffs are already fetched daily, so the wider coverage is free. Diffs are region-scoped: US keys are `changes:{catalog,diff}:{key}` from Watchmode, India keys are `changes:{catalog,diff}:IN:{key}` from TMDB discover snapshots (Watchmode's source list is US-centric; TMDB has no provider "coming soon" feed, so IN diffs cover added/left only). `prefs.region` picks the diff set — IN free users match the six mainstream India services, IN Plus matches all `IN_TRACKED_PROVIDERS`; any other region falls back to US. The weekly digest and the ICS calendar feed use the same region routing, digest falling back to US items on a quiet IN week. Plus subscribers can also route alerts off email entirely: a Discord webhook (`gm:alerts:discord`, validated `discord.com/api/webhooks/*` only) gets an embed, and/or Telegram DMs (`gm:alerts:telegram`, email → chat_id — connect via `POST /api/telegram/link` → `tglink:{token}` (1h TTL) → `t.me/<bot>?start=<token>` → `/api/webhooks/telegram` resolves the `/start` deep link; `/stop` or `DELETE /api/telegram/link` disconnects). Any subscriber including free can enable Web Push per device — `gm:alerts:push` (email → `[{endpoint, keys:{p256dh, auth}, createdAt}]`, ≤5 subs/email) via `POST/DELETE /api/alerts-push`, same email+synckey auth as alerts-prefs plus an allowlist of real push-service hosts (FCM/APNs/Mozilla/WNS) so stored endpoints can't be used for SSRF; the cron sends to every stored sub ahead of the email fallback and prunes 404/410 endpoints. iOS only delivers push to installed PWAs, so `PushAlerts` gates the button behind Add-to-Home-Screen instructions. Resend is the fallback when every configured channel fails. Unsubscribing (`waitlist-remove.ts`) clears all of that email's `gm:alerts:*` entries (prefs, synckey, notified, trakt, discord, telegram, push, share) plus the `gm:share:lookup` reverse index.

## Billing (Galaxy Plus)

Plus is a paid tier sold through Polar as merchant of record — there is no account system; the alerts `email + synckey` pair is the login (`getLinkedEmail`/`isPlusSubscriber` in `src/utils/billing.ts`). `POST /api/webhooks/polar` verifies Standard Webhooks signatures (HMAC key is the literal secret string; a stripped/base64 variant is also tried) and writes `gm:billing` (email → `{status, subscriptionId, customerId, currentPeriodEnd}`) keyed by `metadata.email` stamped at checkout — the sync identity, so a different payment email on Polar's hosted page doesn't re-key it. `POST /api/billing/recover` mails the link-device URL to any address holding a billing record (generic response either way) — the recovery path for subscribers whose sync key was cleared (e.g. via unsubscribe). `isPlusActive` treats `active`/`trialing` and `canceled`-but-before-period-end as entitled. Plus unlocks: chat rate limit 100/hr (per-email bucket vs free 10/hr per-IP) plus a 16-turn history window and synced profile fallback, `leaving` alerts off `ProviderChanges.left`, `taste` alerts — rec lists seeded by the subscriber's ≥7-rated titles, cached per source title in `recs:v1:{type}:{id}` (30d TTL, shared across subscribers, MGET-warmed, ≤25 TMDB backfills/run), `episode` alerts — `next_episode_to_air` from `/tv/{id}` on watchlisted shows (≤40 fetches/run in the same cron, day-rotated when the unique-show set exceeds the cap, deduped per-episode in `gm:alerts:notified`), all-provider alert matching, raised sync caps (1,000 watchlist / 2,500 ratings vs 200/500), two-way Trakt sync (`sync` pushes, `import` GETs `sync/watchlist|ratings/{movies,shows}` and server-merges unseen ids into stored prefs — both use the shared `traktAccessToken` refresh helper in `trakt.ts`), Letterboxd CSV import (client-parsed via `importLetterboxd.ts` → `POST /api/resolve-titles` exact-match batch resolver) and export, synced chat history (`gm:alerts:chat`, 30 turns, via `/api/chat-history`), an ICS calendar feed of watchlisted releases + next episodes + theatrical premieres (24h per-id LRU), a "Picked for you" rail (`GET /api/plus-recs` reads the shared `recs:v1:*` index, ≤5 backfills, 10-min per-email LRU), a "Leaving this month" section in the weekly digest off `changes:monthly:*`, Discord-webhook alerts, and a shareable public list link. Checkout is `POST /api/billing/checkout` (requires linked creds); portal is `GET /api/billing/portal`; `GET /api/billing/status` exposes `entitlement` to the client (`usePlusStatus` hook) and, for Plus accounts only, also returns perk state (`traktConnected`, `shareId`, `discordWebhook`) in the same round-trip. Env: `POLAR_ACCESS_TOKEN`, `POLAR_WEBHOOK_SECRET`, `POLAR_PRODUCT_MONTHLY`, `POLAR_PRODUCT_YEARLY`; `POLAR_API_BASE` overrides the API origin (sandbox is `https://sandbox-api.polar.sh`). Unsubscribing from emails does NOT cancel a subscription — only the Polar webhook mutates `gm:billing`.

Perk plumbing lives in `waitlistStore.ts`: `gm:alerts:trakt` (email → `{refreshToken}` — Trakt OAuth via `/api/trakt/{connect,callback,sync,disconnect}`; `state` is an HMAC-signed payload of the sync creds, no nonce store), `gm:alerts:discord` (email → webhook URL, set through `POST /api/alerts-prefs`'s optional `discordWebhook` field — absent leaves it, `''` clears), `gm:alerts:telegram` (email → chat_id; the pending deep-link token lives at `tglink:{uuid}` with a 1h TTL), and `gm:alerts:share` + `gm:share:lookup` (email ↔ shareId pair backing `POST/DELETE /api/share-link` and the public `/list/[shareId]` page — a deliberately separate read-only token since the synckey is a write credential), and `gm:alerts:chat` (email → `{messages, links, updatedAt}`, ≤30 turns — synced chat history, in the unsubscribe cleanup list). `GET /api/calendar?email&key` renders watchlisted `coming` releases as ICS; `left` items carry no date so departures can't be events. The `PlusTools` component on `watchlist.tsx` is the management UI for all of it.

## Environment

Copy `.env.example` (if present) or set: `TMDB_API_KEY`, `NEXT_PUBLIC_SITE_URL`, `UPSTASH_REDIS_KV_REST_API_URL`, `UPSTASH_REDIS_KV_REST_API_TOKEN`, `OPENAI_API_KEY`, `WATCHMODE_API_KEY`, `RESEND_API_KEY`, `CRON_SECRET`, `TAKEADS_PUBLIC_KEY`. Without `TAKEADS_PUBLIC_KEY`, watch-provider links fall back to plain provider homepages instead of affiliate tracking links. Optional: `WATCHMODE_DAILY_LOOKUP_BUDGET` (default 300), `RESEND_FROM`, `POLAR_*` (billing — see "Billing (Galaxy Plus)"; endpoints 503 without them), `TRAKT_CLIENT_ID` + `TRAKT_CLIENT_SECRET` (Trakt sync — the OAuth app's redirect URI must be `${NEXT_PUBLIC_SITE_URL}/api/trakt/callback`; routes 503 without them), `TELEGRAM_BOT_TOKEN` + `TELEGRAM_WEBHOOK_SECRET` (Telegram alerts — register `/api/webhooks/telegram` once via Bot API `setWebhook` with `secret_token` set to the secret; routes 503/401 without them), `NEXT_PUBLIC_UMAMI_WEBSITE_ID` (Umami analytics; has a committed fallback ID so it works with no env). `NEXT_PUBLIC_WEBPUSH_PUBLIC_KEY` + `WEBPUSH_PRIVATE_KEY` + `WEBPUSH_SUBJECT` (Web Push VAPID — generate once with `npx web-push generate-vapid-keys`; without them the push channel silently no-ops and `/api/alerts-push` still accepts subs it can't send to, so treat the pair as required for the feature). The tracker script and its `/api/send` beacon are proxied first-party via `rewrites()` in `next.config.ts` (`/assets/starfield.js`, `/starfield/api/send`) because the umami.is origins are ad-blocked; `NEXT_PUBLIC_UMAMI_SRC` overrides the script URL — an external/self-hosted origin also needs CSP entries there. Never commit `.env.local`.

For OpenAI spend/usage reporting, run `OPENAI_ADMIN_KEY=... node scripts/openai-usage.js [days]` — requires an org admin key, not the runtime `OPENAI_API_KEY`. Optional: `OPENAI_MODEL` overrides the shared model in `src/utils/openai.ts` (default `gpt-6-luna`, `reasoning_effort: none`); bump the `*_CACHE_VERSION` constants when switching models so cached generations don't mix.

`/usage` is a private dashboard aggregating Worker/Upstash/OpenAI/Polar/internal counters via `GET /api/usage` (Bearer `USAGE_DASH_TOKEN`, 30/hr per IP, 60s server cache). The token travels in the URL fragment (`/usage#token=…`) like the synckey flow, never in query strings. Panels degrade to "not configured" per source: `CF_ACCOUNT_ID` + `CF_ANALYTICS_API_TOKEN` (account token, Analytics:Read — intentionally not `CLOUDFLARE_API_TOKEN`, which sync-cf-secrets drops as wrangler auth), `UPSTASH_EMAIL` + `UPSTASH_API_KEY` (management API key — full account access; `UPSTASH_DATABASE_ID` optional, auto-resolved by matching `UPSTASH_REDIS_KV_REST_API_URL`'s host), `OPENAI_ADMIN_KEY`. Polar needs nothing extra (`POLAR_ACCESS_TOKEN` + `POLAR_API_BASE` are reused); Resend/Umami/TMDB have no usable quota API so they're link cards. Per-source budget caps in `usageSources.ts` are display-only copies of the `checkGlobalBudget` call-site constants — update both when one changes.

## Search Console

GSC is reachable through the `openseo` MCP — project `Galaxy Movies` (id `13219778-f63d-4914-8350-47122b2c3a4a`), connected property `https://www.galaxymovies.app/` (URL-prefix; `galaxymovies.app` is also verified as a domain property). `inspect_urls` gives per-URL index verdicts (≤10/call), `get_search_console_performance` pulls Search Analytics. Google has no API for the Coverage report's aggregate buckets — batch-inspect sitemap URLs instead. The sitemap only emits URLs the pages themselves won't noindex: region-locked provider×genre combos are filtered to `DEFAULT_REGION` availability and overview-less titles are skipped (see `sitemap.xml.ts`).
