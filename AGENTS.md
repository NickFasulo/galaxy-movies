# Galaxy Movies

Next.js 15 Pages Router app (React 19, Chakra UI, @tanstack/react-query v5). All application code is strict TypeScript under `src/` — `allowJs` is off, so new source files must be `.ts`/`.tsx`.

## Commands

- `npm run typecheck` — `tsc --noEmit`, which resolves to native TypeScript 7 via the `@typescript/native` alias. `typescript` itself points at `npm:@typescript/typescript6` so tools needing the classic JS API (typescript-eslint, `next build`'s typecheck step) keep working — TS 7.0 ships no API. Collapse back to a plain `typescript` dep once typescript-eslint supports TS ≥7.1 (typescript-eslint/typescript-eslint#10940).
- `npm test` — Vitest unit tests, colocated as `src/**/*.test.ts` (config `vitest.config.ts`)
- `npm run test:coverage` — same suite + v8 coverage floor (70 lines / 67 stmts / 65 fns / 60 branches, ~3pts under current baseline — a ratchet, tighten as coverage climbs). CI runs this instead of `npm test`.
- `npm run lint` — ESLint flat config (`eslint.config.mjs`, `next/core-web-vitals` + `next/typescript`)
- `npm run check` — typecheck + production build
- `npm run smoke` — post-deploy probe (`scripts/smoke.sh`); `SMOKE_BASE=<url>` retargets it (e.g. the workers.dev host), `SMOKE_LEVEL=core` drops the Redis-backed API + apex checks for secret-less environments.
- `npm run index:check` — URL Inspection API over the top upcoming US+IN releases (`--top N`); needs `.secrets-gsc.json` service-account key added as a GSC user. Prints pre-filled inspect links for unindexed pages — Google's "Request indexing" is UI-only (the Indexing API is JobPosting/BroadcastEvent-only). Repeatable agent flow lives in `.devin/skills/indexing-check/`. The `/api/cron/indexing-report` cron (Mon 14:00 UTC) runs the same check in the worker via `src/features/indexing/indexCheck.ts` — WebCrypto JWT from `GSC_CLIENT_EMAIL`/`GSC_PRIVATE_KEY` (escaped `\n`) env secrets since workerd can't read `.secrets-gsc.json` — and emails `INDEXING_REPORT_EMAIL` (default fasulo.nick@gmail.com) a weekly GSC report: pending pages with inspect links (NEW-marked vs the `gm:indexing:last-report` signature), week-over-week clicks/impressions, top pages, click movers, newly-appearing queries, the `/lists/` position-band tracker (bands persisted in `gm:gsc:lists-bands` for week-over-week shifts), a monthly first-Monday CTR-gap section, and a sitemap resubmit + status — all via `src/features/indexing/gscAnalytics.ts` on the same SA (Full user, `webmasters.readonly` scope).
- `npm run smoke:workerd` — boots the last `cf:build` output under `wrangler dev` (real workerd) and runs the core smoke set; forwards `TMDB_API_KEY` via `--var` when set since wrangler doesn't read `.env.local`.
- `npm run test:e2e` — Playwright (Chromium) specs in `e2e/*.spec.ts`; needs `npx playwright install chromium` once. Boots `next dev` on :3100 with the spend-capable env vars (OpenAI/Upstash/Resend/Watchmode/Umami) emptied — `.env.local` still supplies `TMDB_API_KEY`, but nothing can spend or write. `E2E_BASE_URL=<url>` skips the web server and points at any running target (e.g. the workers.dev host — never prod's custom domain, its WAF managed-challenges datacenter navigations). `npm run test:e2e:ui` opens the Playwright UI.
- `npm run test:e2e:workerd` — `scripts/e2e-workerd.sh` boots the last `cf:build` output under `wrangler dev` :8789 (needs `TMDB_API_KEY` in env; exits early without it) and runs the same suite. `e2e.yml` runs this daily at 16:30 UTC after a fresh `cf:build` — scheduled, non-blocking.
  - Spec conventions: assert stable ids (Fight Club `/movies/550`, GoT `/tv/1399`) and structure, never volatile trending order; every spec imports `test`/`expect` from `e2e/fixtures.ts` (fails the test on any uncaught `pageerror`). Plus/account flows seed `gm.alerts.v1` creds via `addInitScript` and stub the app's own `/api/*` fetches with `page.route` through `e2e/helpers.ts` `stubAccountApi` — never submit forms against the real backend (waitlist/alerts POSTs write Redis + send email). Real Trakt OAuth and Polar checkout stay outside e2e; their server logic is unit-tested in `features/billing/`.
- husky `pre-commit` runs typecheck + lint + test (~8s, suite is fast); `git commit --no-verify` skips.
- `npm run dev` — dev server on :3000 (webpack). `npm run dev:turbo` runs Turbopack, but Next 16.4.0 has a Pages Router Turbopack dev bug (vercel/next.js#99789) that hydration-crashes pages with "module factory is not available" — keep `dev` on webpack until the backported fix ships, then swap the flags back.

## Deploys

**Production = Cloudflare Workers.** `galaxymovies.app` DNS is on Cloudflare; `npm run cf:deploy` builds + deploys the Worker to the custom domain. `main` allows direct pushes — **commit and push directly to `main` by default**; only use a branch for large implementations that warrant a plan/review. (Branch protection exists but only requires the `check` status for PR merges — direct pushes are unaffected.) Dependabot PRs auto-merge via `dependabot-automerge.yml` once `check` goes green — CI secrets on Dependabot runs resolve from the separate Dependabot secret store (`gh secret list --app dependabot`), so `TMDB_API_KEY`/`WATCHMODE_API_KEY` must exist in both scopes or every Dependabot CI run fails at `smoke:workerd`. `ci.yml` runs on pushes and PRs: typecheck, lint, `test:coverage`, `cf:build` (deliberately not `next build` — that compiles Turbopack while prod is webpack, and only cf:build exercises the opennext adapter + postbuild + patches), then `smoke:workerd` — the built bundle boots under `wrangler dev` and gets smoke-checked so workerd-only breakage fails in CI, not at deploy. (@cloudflare/vitest-pool-workers was the alternative; it pins `vitest@^4` — revisit if vitest 5 support lands.) Scheduled jobs: `contract.yml` runs live TMDB/Watchmode contract tests Mondays (skipped elsewhere — keeps per-push CI keyless; needs `WATCHMODE_API_KEY` repo secret, job fails if secrets absent), `lhci.yml` runs Lighthouse budgets Wednesdays, `prod-smoke.yml` runs `smoke.sh` at full level against prod daily (secretless — the probe is unauthenticated). `preview.yml` uploads a `wrangler versions` preview for same-repo PRs and comments the URL — needs `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID` repo secrets and is excluded from fork PRs because preview versions share the worker's production bindings. After `cf:deploy`, run `npm run smoke` against prod. Merged PR branches auto-delete.

Vercel is **cold standby only** — no domain points at it, its crons are disabled (dashboard → Settings → Cron Jobs), and `git.deploymentEnabled: false` in vercel.json stops all Git-triggered deploys (every branch, not just `main`). Rollback = re-add `A galaxymovies.app → 216.198.79.1` + `CNAME www → 2144276a1a31ddeb.vercel-dns-017.com` in Cloudflare DNS (traffic flips back instantly — Worker custom domains only take precedence while they're the only records), re-enable Vercel crons. Vercel teardown checklist once fully decommissioned: remove the domain from the project, delete crons, downgrade team to Hobby/cancel Pro. Previews still work via `vercel deploy --scope nickfasulos-projects` (CLI deploys are unaffected by `deploymentEnabled`).
- `npm run lhci` — build + Lighthouse CI (`lighthouserc.cjs`)

## Cloudflare Workers deploy

The app runs on Cloudflare Workers via `@opennextjs/cloudflare` (deployed to `galaxymovies.app` + `www` custom domains; `galaxy-movies.winter-rice-c91a.workers.dev` also stays live). `npm run cf:build` runs the adapter build plus `scripts/opennext-postbuild.js`, which (a) drops stub modules for dev-only `require()`s the adapter marks external (see `patches/@opennextjs+cloudflare+*.patch`, applied by `postinstall` — re-run `npx patch-package @opennextjs/cloudflare` if edits drift), (b) copies `public/fonts` + `backdrop_fallback.jpg` to `.open-next/public/` because workerd's `fs` cwd is `/bundle`, and (c) writes `.open-next/entry.js` — the worker entry that wraps the generated `worker.js` with a `scheduled()` handler reproducing the `vercel.json` crons via the `WORKER_SELF_REFERENCE` service binding (same `Bearer CRON_SECRET` auth). `wrangler.jsonc` sets `main` to that entry, `triggers.crons`, the `NEXT_INC_CACHE_R2_BUCKET` R2 binding (ISR cache — create the bucket once: `wrangler r2 bucket create galaxy-movies-inc-cache`), and `find_additional_modules` + `rules` so the og fonts ship in the vfs. `npm run cf:preview` builds + `wrangler dev` (add `--test-scheduled` to fire crons at `/__scheduled?cron=<expr>`); `npm run cf:secrets` pushes `.env.local` values as worker secrets; `npm run cf:deploy` builds + deploys to `galaxy-movies.<account>.workers.dev`. `/api/og` imports `@vercel/og`'s edge entry on workerd (detected via `navigator.userAgent === 'Cloudflare-Workers'`) because the node entry uses `readFileSync` + runtime `WebAssembly.instantiate`, both disallowed; `useWorkerdCondition` externals force-copy emotion/uncrypto packages whose ESM builds sit behind `workerd` export conditions. Node APIs are fetch-only (Upstash REST, OpenAI, Resend) — no TCP clients, so nothing else needs polyfills. `/api/og` + `/api/og-leaving` store renders via `caches.default` (`src/lib/edgeCache.ts`) — `s-maxage` on a Worker response does NOT make the CF edge cache keep API-route/HTML responses (Vercel-CDN-Cache-Control is inert there), so preview bots would re-run the resvg pipeline per hit without it. The same gap means `setSwrCache` gives GSSP pages no edge HTML cache — every request SSRs.

## Conventions

- Shared TMDB/API types live in `src/types/tmdb.ts`; env var declarations in `src/types/env.d.ts`.
- Code is organized as feature modules: `src/features/{catalog,alerts,billing,ai,social,monetize}/` holds each domain's services, `hooks/`, and `components/`; `src/hooks/` is for app-wide hooks; `src/lib/` is cross-cutting infra (redis, auth, rateLimiter, ssr, site, imageLoader — referenced by literal path in `next.config.ts`) plus `lib/format/` helpers; `src/components/` is shared UI only. `src/pages/` is routes — Pages Router ties API URLs to file paths, so route files stay thin and call into features/lib.
- Design tokens live in `src/theme.ts` (Chakra `createSystem`): `surface.*` colors, `brand.*` accents, `border.subtle`, and the `fonts.display` brand face — use them instead of hardcoding the dark grays. Body font is self-hosted Inter (`public/fonts/inter-var-latin.woff2`, `@font-face` in globals.css); `next/font` can't be used in `_document` on the Pages Router, so fonts are always self-hosted there. The `Inter-*.ttf` files are for `next/og` only.
- Detail pages with server-side error props split the error view into a separate component so hooks never run conditionally (see `CompanyContent`/`CompanyErrorView` pattern).
- Three workerd-vs-Node render traps the e2e suite caught (all invisible to curl smoke): (1) never emit `<script>` whose source comes from a function's `.toString()` — OpenNext's esbuild keepNames rewrites inner fns to `__name(...)` which doesn't survive stringification and crashes in the browser; that's why `next-themes` is gone and `_document.tsx` stamps `class="dark"`/`color-scheme` statically. (2) Any locale/TZ-dependent text (`toLocaleDateString`, `new Date()` month labels) must pin `timeZone:'UTC'` — SSR runs in UTC but hydration uses the viewer's TZ → React #418 mismatch; `lib/format/formatters.ts` `dateFormatter` is the pattern. (3) `notFound` on dynamic routes renders Next's built-in 404 under workerd, not `pages/404.tsx` — OpenNext gap, so e2e asserts status + generic not-found copy.
- `src/pages/api/og.tsx` renders `next/og` markup — raw `<img>` is required there and ESLint rules are disabled for that file only.
- `src/lib/imageLoader.ts` is the global `next/image` loader — referenced by `next.config.ts` `images.loaderFile` as a string path, so import-graph/dead-code scans can't see it. Do not delete it.
- All backdrop imagery renders through `src/components/Backdrop.tsx` (`BACKDROP_OVERLAYS` gradient presets, `BACKDROP_FALLBACKS` local art). Local art is generated by `node scripts/generate-backdrop-fallback.js` (seeded, deterministic); the /plus page's spiral-galaxy variant is `node scripts/generate-plus-backdrop.js` (`BACKDROP_FALLBACKS.plus`), and the PWA/touch icons in `public/icons/` are `node scripts/generate-icons.js` (centered spiral; maskable variants shrink the galaxy into the 80% safe zone). The email header wordmark `public/email-logo.png` is `node scripts/generate-email-logo.js` — it renders "Galaxy Movies" in SpaceRangerLaserItalic via `next/og` with the homepage glow baked in since Gmail/Outlook drop SVG images and can't be trusted to load web fonts (`logo.svg` is the separate galaxy-display face, not the site font — don't use it for the wordmark). `public/sw.js` is a push-only service worker (no fetch handler — it never touches page loads). The card-hover backdrop swap is homepage-only: `useHoverBackground` + `<HoverBackground>` in `src/components/HoverBackground.tsx`, wired in `src/pages/index.tsx`. It must render inside the page's `zIndex={1}` content box — mounted in `_app`, the root Flex's opaque `bg` paints over it.
- `scripts/` is plain JS build tooling, excluded from tsconfig and ESLint.
- `/embed/[provider]` is the iframe widget for third-party sites (daily diff lists + "Powered by" attribution, `?theme=light` variant). `/embed/*` is excluded from the global `X-Frame-Options`/`frame-ancestors` headers in `next.config.ts` and `_app` renders it without chrome or localStorage hooks. `/widgets` is the embed-code landing page; `GET /api/streaming-changes?provider={key|all}` is the open JSON feed (CORS `*`, 120/hr per-IP, `changes_rl` bucket). Embeddable providers = `PROVIDER_NAME_MATCH` ∩ `streamingProviders` (`isEmbeddableProvider` in `src/features/catalog/embed.ts`) — US-only since IN diffs carry no `coming` data.
- Upstash free tier bills every command — including each member of a pipeline — so per-request paths must minimize Redis ops: prefer `HGETALL`/`MGET`/hash storage over per-key fan-out, batch counter updates in memory before flushing, and don't add Redis reads to SSR hot paths without counting the quota cost.
- Per-IP rate limits can't stop distributed floods (rotating IPv6/proxy botnets send clean browser UAs, one request per address) — API endpoints that fan out to TMDB/upstream also carry a global hourly `checkGlobalBudget` circuit breaker (`global_rl:discover` 2,000/hr, `global_rl:price` 100/hr uncached). Once a global budget trips, `isGlobalBudgetTripped` denies for 60s per isolate without touching Redis, so the flood's own re-checks don't bill commands. IPv6 client ids are bucketed to /64 in `checkDistributedRateLimit`. Global budget counter keys are `global_rl:{name}:all` (the `:all` clientId suffix is easy to drop when reading them, e.g. the /usage panel). Separately, upstream Watchmode quota is guarded by `features/catalog/watchmodeQuota.ts`: `X-Account-Quota[-Used]` response headers persist to `wm:quota` (6h TTL) on every call, price lookups refuse upstream at ≥90% used (reserving the tail for the streaming-changes cron), the cron stands down at ≥99%, and the `/usage` panel shows a live `/status` probe plus the last header sample.
- Crawler policy is enforced in two layers that must stay in sync, and the edge half is NOT in this repo — it lives in the zone's WAF custom ruleset (dashboard → Security → WAF, or the rulesets API with `CLOUDFLARE_API_TOKEN` which carries `#waf:edit`): `cf.client.bot` skip → ASN/scanner-path block → AI-training-crawler UA block (ClaudeBot/GPTBot/CCBot/...) → `managed_challenge` on verified-bot `/api/*` → `managed_challenge` "Challenge navigations" on the content paths (/movies/, /tv/, /leaving/, /new-on-streaming, ...). The navigations rule exempts verified bots and the referral-AI families, which deliberately mirror `CRAWLER_BUDGETS` in `src/lib/crawlerThrottle.ts` — add or drop a family in both places or the middleware budget becomes unreachable dead code. UAs are spoofable, so the exemption is IP-pinned where the operator publishes ranges (`perplexity*` → perplexitybot.json + perplexity-user.json, `claude-searchbot|claude-user` → claude.com/crawling/bots.json, `oai-searchbot` → openai.com/searchbot.json — point-in-time snapshots baked into the expression; refresh if a family's real traffic starts 403ing again); `chatgpt-user`, `amzn-searchbot`, `exasearchbot` stay UA-only (lists too big to inline; real Exa requests are Web Bot Auth-signed so `cf.client.bot` covers them). Do NOT substitute ASN checks for the published lists — Perplexity's crawler IPs span multiple ASNs (an earlier `asn eq 14618` exemption silently missed its AT&T-announced 18.97.x range). The challenge answers bots with 403 + `cf-mitigated: challenge`, which AI Crawl Control metrics count as blocked even though it's a challenge, not a rule block.

## Title-level surfaces

`updateStreamingChanges` also writes `changes:index:US` (hash field `${type}:${tmdbId}` → `{coming, leaving, added, left}` events built from the monthly diffs) so detail pages can answer "is X still on Netflix" without per-provider reads — `getTitleChanges` does one `HGET` behind a 10-min LRU and drops `coming`/`leaving` entries whose dates have passed. The `TitleAvailability` sidebar block on detail pages renders those notices plus the single-title alert form. Title alerts are a separate audience from waitlist subscribers: `POST /api/alerts-watch` → `gm:alerts:watch-pending` → `alerts-watch-confirm` → `gm:alerts:watch` (email → `{unsub, titles[]}`); the watchlist-alerts cron matches them against all-provider diffs and drops a title once its `added` notification sends. `waitlist-remove` accepts the watch `unsub` token as a fallback after the waitlist token check and clears both hashes on full unsubscribe. `/this-month/[provider]` renders arrivals-vs-departures verdicts from `changes:monthly:*`; `/api/og-leaving?provider=` renders the shareable leaving card via the same `next/og` edge-import path as `/api/og`; `/api/cron/social-broadcast` posts weekly highlights through every configured channel in `src/features/social/socialChannels.ts` — each is env-gated and reports `skipped`/`posted`/`failed` per run, deduped per channel on post text in `gm:social:last-post:{channel}`: Bluesky (`BSKY_HANDLE`/`BSKY_APP_PASSWORD`), Discord own-server webhook (`SOCIAL_DISCORD_WEBHOOK`), Telegram channel (`TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHANNEL`), Mastodon (`MASTODON_INSTANCE` + `MASTODON_TOKEN`), X (`X_API_KEY`/`X_API_SECRET`/`X_ACCESS_TOKEN`/`X_ACCESS_TOKEN_SECRET`, OAuth 1.0a signed in workerd via `crypto.subtle`), Reddit (`REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET`/`REDDIT_USERNAME`/`REDDIT_PASSWORD`, optional `REDDIT_SUBREDDIT`, link posts to own subreddit only), Tumblr (`TUMBLR_BLOG` + `TUMBLR_ACCESS_TOKEN`), Pinterest (`PINTEREST_BOARD` + `PINTEREST_ACCESS_TOKEN`, pins the `/api/og-leaving` card), Facebook Page (direct `/{page-id}/feed` link post when `FB_PAGE_ID` + `FB_PAGE_ACCESS_TOKEN` exist — the page token never expires when minted from a long-lived user token, and travels in the form body so it stays out of access logs — otherwise it POSTs `{message, link}` to `SOCIAL_FACEBOOK_WEBHOOK`, a Make/Zapier catch hook that publishes via its own approved app, which needs no Meta developer account). A second social cron, `/api/cron/social-monthly` (25th, 17:00 UTC), posts the dated `leavingSoon` departures list through the same channel set via `broadcastMonthlyDepartures`, deduped under `gm:social:last-post:monthly:{channel}` so it can't suppress or resurrect weekly posts; `buildDeparturesPost` returns '' on a month with no scheduled departures so every channel reports `nothing to post`. `/leaving.xml` is an RSS feed of the same diff data, linked via `rel=alternate` on `/leaving`, `/leaving/[provider]`, `/new-on-streaming`. r/galaxymovies posting lives in a separate Devvit app repo (`github.com/NickFasulo/galaxy-movies-devvit`): a weekly scheduler task fetches the public `GET /api/reddit-payload` digest endpoint here and `reddit.submitPost`s it as the app account, deduped by ISO-week key in Devvit Redis, plus a moderator "post now" menu item for manual runs. A `monthly-departures` task (25th, `?kind=leaving`) posts the `buildDeparturesDigest` output — a `buildRedditDigest` variant restricted to dated `leavingSoon` rows — deduped by `YYYY-MM:leaving` payload key, with a matching manual menu item. It needs the `www.galaxymovies.app` fetch-domain approved (requested at upload; migration-program participants can ask r/Devvit for an exception). The legacy `reddit` env channel stays dormant — new OAuth app creation requires manual Reddit approval we can't get.

## Watchlist alerts

Alerts give a confirmed waitlist subscriber (`gm:waitlist:confirmed`, email → unsub token) a separate, independently-rotatable credential — `gm:alerts:synckey` (email → UUID) — minted on first confirm and handed out via URL fragment (`/email-status#email=&key=`) so it never hits server access logs. The client stores it (`gm.alerts.v1` in localStorage) and posts debounced watchlist/ratings/service snapshots to `POST /api/alerts-prefs`, stored in `gm:alerts:prefs` (email → `{watchlist, services, region, ratings, updatedAt}`). `GET /api/alerts-prefs?email&key` returns the snapshot; on confirm, `email-status.tsx` merges it into local storage (`mergeSyncedPrefs`, local wins conflicts) so new devices inherit the profile instead of overwriting it. `GET /api/alerts-link?email&key` re-issues the fragment for linking additional devices; `waitlist.ts` emails that link automatically when an already-confirmed address re-submits the form. The daily `/api/cron/watchlist-alerts` cron (runs after `streaming-changes`) reads `streaming-changes`'s cached diffs, matches each subscriber's watchlist against their chosen providers' `added`/`coming` titles (plus `leaving`/`taste` for Plus subscribers), dedupes against `gm:alerts:notified`, and sends one Resend email per subscriber with matches. Free subscribers match only the base six providers; Plus subscribers match every source in `PROVIDER_NAME_MATCH` — peacock/paramount+ diffs are already fetched daily, so the wider coverage is free. Diffs are region-scoped: US keys are `changes:{catalog,diff}:{key}`, India keys are `changes:{catalog,diff}:IN:{key}` — both regions' catalog snapshots come from TMDB discover (`with_watch_providers` + `flatrate|free|ads` monetization). Watchmode is only used for what TMDB can't give: dated arrivals (`/releases` → `coming`), scheduled departures (`/title-leaving-dates/` → `leavingSoon`, free plan's unfiltered 10-title preview — no tmdb_ids, so items resolve by normalized-title match against the provider's fresh catalog), and `/api/prices`. IN diffs cover added/left only. `prefs.region` picks the diff set — IN free users match the six mainstream India services, IN Plus matches all `IN_TRACKED_PROVIDERS`; any other region falls back to US. The weekly digest and the ICS calendar feed use the same region routing, digest falling back to US items on a quiet IN week. Plus subscribers can also route alerts off email entirely: a Discord webhook (`gm:alerts:discord`, validated `discord.com/api/webhooks/*` only) gets an embed, and/or Telegram DMs (`gm:alerts:telegram`, email → chat_id — connect via `POST /api/telegram/link` → `tglink:{token}` (1h TTL) → `t.me/<bot>?start=<token>` → `/api/webhooks/telegram` resolves the `/start` deep link; `/stop` or `DELETE /api/telegram/link` disconnects). Any subscriber including free can enable Web Push per device — `gm:alerts:push` (email → `[{endpoint, keys:{p256dh, auth}, createdAt}]`, ≤5 subs/email) via `POST/DELETE /api/alerts-push`, same email+synckey auth as alerts-prefs plus an allowlist of real push-service hosts (FCM/APNs/Mozilla/WNS) so stored endpoints can't be used for SSRF; the cron sends to every stored sub ahead of the email fallback and prunes 404/410 endpoints. iOS only delivers push to installed PWAs, so `PushAlerts` gates the button behind Add-to-Home-Screen instructions. Resend is the fallback when every configured channel fails. Unsubscribing (`waitlist-remove.ts`) clears all of that email's `gm:alerts:*` entries (prefs, synckey, notified, trakt, discord, telegram, push, share) plus the `gm:share:lookup` reverse index.

## Billing (Galaxy Plus)

Plus is a paid tier sold through Polar as merchant of record — there is no account system; the alerts `email + synckey` pair is the login (`getLinkedEmail`/`isPlusSubscriber` in `src/features/billing/billing.ts`). `POST /api/webhooks/polar` verifies Standard Webhooks signatures (HMAC key is the literal secret string; a stripped/base64 variant is also tried) and writes `gm:billing` (email → `{status, subscriptionId, customerId, currentPeriodEnd}`) keyed by `metadata.email` stamped at checkout — the sync identity, so a different payment email on Polar's hosted page doesn't re-key it. `POST /api/billing/recover` mails the link-device URL to any address holding a billing record (generic response either way) — the recovery path for subscribers whose sync key was cleared (e.g. via unsubscribe). `isPlusActive` treats `active`/`trialing` and `canceled`-but-before-period-end as entitled. Plus unlocks: chat rate limit 100/hr (per-email bucket vs free 10/hr per-IP) plus a 16-turn history window and synced profile fallback, `leaving` alerts off `ProviderChanges.left`, `taste` alerts — rec lists seeded by the subscriber's ≥7-rated titles, cached per source title in `recs:v1:{type}:{id}` (30d TTL, shared across subscribers, MGET-warmed, ≤25 TMDB backfills/run), `episode` alerts — `next_episode_to_air` from `/tv/{id}` on watchlisted shows (≤40 fetches/run in the same cron, day-rotated when the unique-show set exceeds the cap, deduped per-episode in `gm:alerts:notified`), all-provider alert matching, raised sync caps (1,000 watchlist / 2,500 ratings vs 200/500), two-way Trakt sync (`sync` pushes, `import` GETs `sync/watchlist|ratings/{movies,shows}` and server-merges unseen ids into stored prefs — both use the shared `traktAccessToken` refresh helper in `trakt.ts`), Letterboxd CSV import (client-parsed via `importLetterboxd.ts` → `POST /api/resolve-titles` exact-match batch resolver) and export, synced chat history (`gm:alerts:chat`, 30 turns, via `/api/chat-history`), an ICS calendar feed of watchlisted releases + next episodes + theatrical premieres (24h per-id LRU), a "Picked for you" rail (`GET /api/plus-recs` reads the shared `recs:v1:*` index, ≤5 backfills, 10-min per-email LRU), a "Leaving this month" section in the weekly digest off `changes:monthly:*`, Discord-webhook alerts, and a shareable public list link. Checkout is `POST /api/billing/checkout` (requires linked creds); portal is `GET /api/billing/portal`; `GET /api/billing/status` exposes `entitlement` to the client (`usePlusStatus` hook) and, for Plus accounts only, also returns perk state (`traktConnected`, `shareId`, `discordWebhook`) in the same round-trip. Env: `POLAR_ACCESS_TOKEN`, `POLAR_WEBHOOK_SECRET`, `POLAR_PRODUCT_MONTHLY`, `POLAR_PRODUCT_YEARLY`; `POLAR_API_BASE` overrides the API origin (sandbox is `https://sandbox-api.polar.sh`). Unsubscribing from emails does NOT cancel a subscription — only the Polar webhook mutates `gm:billing`.

Perk plumbing lives in `waitlistStore.ts`: `gm:alerts:trakt` (email → `{refreshToken}` — Trakt OAuth via `/api/trakt/{connect,callback,sync,disconnect}`; `state` is an HMAC-signed payload of the sync creds, no nonce store), `gm:alerts:discord` (email → webhook URL, set through `POST /api/alerts-prefs`'s optional `discordWebhook` field — absent leaves it, `''` clears), `gm:alerts:telegram` (email → chat_id; the pending deep-link token lives at `tglink:{uuid}` with a 1h TTL), and `gm:alerts:share` + `gm:share:lookup` (email ↔ shareId pair backing `POST/DELETE /api/share-link` and the public `/list/[shareId]` page — a deliberately separate read-only token since the synckey is a write credential), and `gm:alerts:chat` (email → `{messages, links, updatedAt}`, ≤30 turns — synced chat history, in the unsubscribe cleanup list). `GET /api/calendar?email&key` renders watchlisted `coming` releases as ICS; `left` items carry no date so departures can't be events. The `PlusTools` component on `watchlist.tsx` is the management UI for all of it.

## Search Console

GSC is reachable through the `openseo` MCP — project `Galaxy Movies` (id `13219778-f63d-4914-8350-47122b2c3a4a`), connected property `https://www.galaxymovies.app/` (URL-prefix; `galaxymovies.app` is also verified as a domain property). `inspect_urls` gives per-URL index verdicts (≤10/call), `get_search_console_performance` pulls Search Analytics. Every apex path 308-redirects to `www` via a `has: host` rule at the top of `redirects()` in `next.config.ts` — the worker serves both custom domains, so without it apex would serve duplicate content under a canonical tag. Google has no API for the Coverage report's aggregate buckets or request-indexing — batch-inspect sitemap URLs for the former; the only programmatic nudge available is IndexNow (Bing/Yandex, not Google), which `updateStreamingChanges` calls at the end of each diff run with every changed detail URL plus the affected `/streaming/{p}`, `/leaving/{p}`, and `/new-on-streaming` pages (`src/lib/indexnow.ts`; the verification key is a public file `public/{key}.txt`). The sitemap only emits URLs the pages themselves won't noindex: region-locked provider×genre combos are filtered to `DEFAULT_REGION` availability and overview-less titles are skipped (see `sitemap.xml.ts`). Listing pages (`ProviderPage`, `ProviderGenrePage`, `OrgPage`) noindex via `getContentIndexability` when the detected region's catalog is thin. The sitemap deliberately does NOT include `/person/`, `/company/`, or `/network/` detail pages (dropped Oct 30, 2026): they were ~42% of submitted URLs for ~1.5% of search clicks, and Google rations crawl on a young domain — the tail was starving the `/leaving/{p}`/`/this-month/{p}`/`/new-on-streaming/{p}` diff pages, which sat at "Discovered - currently not indexed" (never even crawled). The pages still exist for users and index via internal links; don't re-add them to the sitemap without a demonstrated click case. The diff pages emit `changes:monthly:{provider}:{month}.updatedAt` as lastmod (hubs get the newest across providers) — a real change signal, unlike the detail pages' release-date default.
