# Spec: Galaxy Movies browser extension ("Where to Watch" chip + daily-diff popup)

MV3 extension in a **separate repo** (`galaxy-movies-extension`), plain JS, no build step. Distributes via Firefox Add-ons (free), Edge Add-ons (free), Chrome Web Store ($5 one-time, approved), and a GitHub Releases zip for Chrome sideloading.

## Two features

### 1. Where-to-watch chip (content script)

On supported title pages, inject a compact chip: `▶ Netflix · Tubi free →` linking to `https://galaxymovies.app/{movies|tv}/{tmdbId}`.

| Site | Match | Id source |
|---|---|---|
| `imdb.com/title/tt*` | `/title/(tt\d+)` | `imdb_id` param |
| `themoviedb.org/(movie|tv)/*` | `/(movie|tv)/(\d+)` | `id` + `type` params (free — no search needed) |
| `letterboxd.com/film/*` | `/film/([\w-]+)` | parse `title` + `year` from `document.title` / JSON-LD `name`+`datePublished` |
| Google search (`"watch X"`-style results) | optional v2 — skip in v1 |

- Chip data: `GET https://galaxymovies.app/api/ext/where?…&region={stored}` (see `where-api.md`; must land first).
- Render top 3 `flatrate` names + count of `free`/`ads` services; fallback chip text "See where it's streaming" when providers are empty.
- Inject once, idempotent (`data-gm-chip` guard + `MutationObserver` for SPA nav on TMDB/Letterboxd; IMDb is fine on load).
- Style: inline `all: initial`-scoped container or Shadow DOM so site CSS can't clobber it; dark chip matching `surface` palette (`#14181c` bg, brand accent from `src/theme.ts`).
- User's "my services" (options) get a colored highlight in the chip.

### 2. Popup (action)

Three tabs — **New**, **Leaving**, **Coming** — fed by `GET https://galaxymovies.app/api/streaming-changes?provider=all` (CORS already `*`, no backend change needed). Top 8 items per tab filtered to the user's chosen providers; each row links to the title page on galaxymovies.app. Footer: "Full list →" to `/leaving/{provider}`.

### Options page

- Region: US | IN (default US).
- Provider checkboxes (list hardcoded in the repo mirroring `embeddableProviders()` output — ~20 keys; a `PROVIDERS` const at top of `options.js`).
- Chip toggle per site (imdb/tmdb/letterboxd on by default).
- Theme: auto/dark/light for the popup.
- Persist via `chrome.storage.sync`.

## Manifest (v3)

```jsonc
{
  "manifest_version": 3,
  "name": "Galaxy Movies — Where to Watch",
  "version": "1.0.0",
  "permissions": ["storage"],
  "host_permissions": ["https://galaxymovies.app/*"],
  "background": { "service_worker": "background.js" },
  "action": { "default_popup": "popup.html", "default_icon": "icons/48.png" },
  "options_page": "options.html",
  "content_scripts": [{ "matches": ["*://*.imdb.com/title/*", "*://www.themoviedb.org/movie/*", "*://www.themoviedb.org/tv/*", "*://letterboxd.com/film/*"], "js": ["content.js"], "run_at": "document_idle" }],
  "browser_specific_settings": { "gecko": { "id": "where-to-watch@galaxymovies.app", "strict_min_version": "121.0" } }
}
```

All API fetches run in `background.js` (host_permissions make it CORS-exempt), content script talks to it via `chrome.runtime.sendMessage`. Popup can fetch directly but route it through the background worker too — one caching layer: `chrome.storage.local` cache of `/api/ext/where` results keyed `type|region|query`, 6h TTL, keeps us polite against the `ext_where_rl` bucket.

## Repo layout

```
galaxy-movies-extension/
  manifest.json
  background.js        # fetch + cache layer, message handlers
  content.js           # chip injection per site
  popup.html/.js/.css  # diff tabs
  options.html/.js/.css
  icons/               # copied from main repo public/icons (16/32/48/128 crops)
  scripts/package.sh   # zip dist for each store + git tag flow
  store-assets/        # screenshots, descriptions (untracked or docs/)
```

Icons: reuse `public/icons/icon-192.png`/`icon-512.png` from this repo (generated by `scripts/generate-icons.js`); crop sizes as needed. No new art.

## Backend touchpoints in this repo

- `GET /api/ext/where` — new (spec: where-api.md).
- `GET /api/streaming-changes` — existing, CORS `*` already set.
- No other changes; do **not** relax `rejectBot` on `/api/watchProviders` — the extension uses `ext/where`, not the internal batch endpoint.
